# Codex 执行效率

Wise 的交互式 Codex 会话通过 app-server 执行。执行效率由实际模型、推理强度、任务上下文和工具使用方式共同决定；命令数量不是单独的质量指标。

## 原生运行能力

Wise 使用本机 Codex 二进制和原生工具循环，并在任务仓库目录启动 app-server。原生配置和登录态路径统一遵循 `CODEX_HOME`，未设置时使用 `~/.codex`；缓存也按目录隔离。

切换供应商档案时，档案中明确设置的值优先；未提供的原生配置递归保留，包括 features、MCP、插件、技能、项目设置、指令和权限。供应商的同名定义整体替换，避免继承上一地址的凭据字段。合并过程中发现无效 TOML 时返回错误，不能通过覆盖来丢弃原配置；内容没有变化时跳过配置写入。该修复也作用于保留的 `codex exec` 后端。

未在 Wise 中选择模型时，不再把用户级默认模型强行作为 RPC 覆盖值传入；由 Codex 解析项目配置与运行配置。新建、续接会话均采用服务端返回的实际模型处理图片输入。明确选择的模型和权限设置仍按原逻辑传递。

这不会自动安装 Codex 桌面端专属连接器或强行开启实验功能。可用工具仍由本机 Codex 版本、账号、配置和已安装插件决定。能力缺失时先检查这些配置；不要通过反复执行 shell 命令模拟已经提供的原生工具。

## 默认执行约定

`src-tauri/src/prompts/efficient_execution.md` 随普通交互回合注入，要求搜索收敛、独立读取批量执行、复用结果、根据证据修改、保存测试完整日志及真实退出码、等待已有异步进程。必要验证和用户明确要求优先，不设置强制命令上限，不自动降低推理强度或更换模型。

约定使用独立的文本 input item，在图片提取之后加入；不会覆盖 config.toml、AGENTS.md 或原始用户正文。Wise 自有转录仍保存原始输入，Codex 原生记录包含该上下文。首次接受的普通回合注入，之后每八个普通回合刷新一次；重启应用或缓存淘汰后重新计数。新会话和续接会话都生效；只读短任务、空输入和以 `/` 开头的原生命令不注入。优先使用已提供的原生工具，批量独立读取、复用证据，避免反复探测或重建现有能力。它是模型工作约定，不是工具层缓存、拦截器或性能保证。

## 续接配置

`thread/resume` 与 `thread/start` 一样传递当前解析出的 model、cwd 和 sandbox/approval 配置，避免界面选择了新模型但旧 thread 继续使用旧模型。每轮推理强度仍由 `turn/start.effort` 传递。未指定的配置不强行填入默认值，供应商切换时新建 thread 的兼容逻辑保留。

## 连续回合复用

正常完成的交互回合短时保留原生 app-server。相同标签、原生 thread 和启动配置的续聊直接 `turn/start`，省去重复进程启动、initialize 和 thread/resume，也保留该进程内的运行状态。每轮推理强度仍然独立传递。

最多保留 4 个空闲进程，空闲 120 秒后关闭；超额淘汰最早空闲者。新会话、模型/权限/供应商/登录配置改变、二进制更新，以及用户/项目 config.toml、profile overlay、AGENTS 文件改变时重新启动。只读短任务、失败、中断、取消或失联的进程不复用；关闭会话和退出应用也会清理空闲进程。未处理完的控制请求仍持有会话时，按原流程关闭。缓存不重放用户请求，也不在 turn/start 结果不确定时自动重试。

原生 `turn/completed` 的状态、错误和 ID 从嵌套的 `turn` 对象解析，同时兼容旧格式。其他 thread 或旧回合的结束通知不能终止当前回合。日志提供 `runtime=cold/reused` 和 `turn_dispatched_in_ms`，便于区分启动开销与模型执行耗时。

## 验收方式

选取同一代码快照、任务、模型/供应商和推理强度，分别在新会话运行；记录到首个有效定位、首个修改和完成的耗时，以及实际工具调用数、重复搜索与测试次数、验证结果。至少多次重复后比较，不把先前已经修复的工作区作为另一组输入，也不只比较 UI 聚合后的“执行命令”数字。

回归测试覆盖：原生工具配置保留、显式关闭设置优先、供应商凭据字段不串用、TOML 合并幂等与错误处理、`CODEX_HOME` 路径选择、服务端实际模型解析，以及既有的输入、续接配置和效率提示测试。没有同条件真实任务 A/B 数据时，不宣称命令数或耗时下降的百分比。

复用测试通过本地模拟 app-server 验证两轮只进行一次 initialize/thread/start、第二轮输入和推理参数正常传递、事件接收器可移交；另覆盖配置失效、容量上限、过期、移除和清空，以及原生失败/中断事件解析。它证明省去了哪些启动步骤，不代表真实任务工具调用数已有定量下降。

协议依据：[OpenAI Codex App Server 文档](https://learn.chatgpt.com/docs/app-server)。桌面宿主提供的额外工具不等于所有 app-server 客户端自动拥有的工具。

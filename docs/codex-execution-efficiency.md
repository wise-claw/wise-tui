# Codex 执行效率

Wise 的交互式 Codex 会话通过 app-server 执行。执行效率由实际模型、推理强度、任务上下文和工具使用方式共同决定；命令数量不是单独的质量指标。

## 默认执行约定

`src-tauri/src/prompts/efficient_execution.md` 随普通交互回合注入，要求搜索收敛、独立读取批量执行、复用结果、根据证据修改、保存测试完整日志及真实退出码、等待已有异步进程。必要验证和用户明确要求优先，不设置强制命令上限，不自动降低推理强度或更换模型。

约定使用独立的文本 input item，在图片提取之后加入；不会覆盖 config.toml、AGENTS.md 或原始用户正文。Wise 自有转录仍保存原始输入，Codex 原生记录包含该上下文。新会话和续接会话都生效；只读短任务、空输入和以 `/` 开头的原生命令不注入。它是模型工作约定，不是工具层缓存、拦截器或性能保证。

## 续接配置

`thread/resume` 与 `thread/start` 一样传递当前解析出的 model、cwd 和 sandbox/approval 配置，避免界面选择了新模型但旧 thread 继续使用旧模型。每轮推理强度仍由 `turn/start.effort` 传递。未指定的配置不强行填入默认值，供应商切换时新建 thread 的兼容逻辑保留。

## 验收方式

选取同一代码快照、任务、模型/供应商和推理强度，分别在新会话运行；记录到首个有效定位、首个修改和完成的耗时，以及实际工具调用数、重复搜索与测试次数、验证结果。至少多次重复后比较，不把先前已经修复的工作区作为另一组输入，也不只比较 UI 聚合后的“执行命令”数字。

本次回归测试覆盖：用户输入与非视觉附件保留、续轮输入不累积、空输入与原生命令不注入、只读任务不注入，以及续接配置序列化与新建会话一致。

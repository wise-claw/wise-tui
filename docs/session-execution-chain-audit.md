# 会话执行链路检查与优化（2026-10-09）

本次检查覆盖前端的会话解析、派发门闸、上下文准备后的引擎调用、事件订阅、轮次完成和问题续接，并对照后端的 invocation / session 通道及执行登记机制。修复集中在前端生命周期与路由，不修改后端命令、历史数据或引擎接口。

## 已修复问题

| 触发条件 | 原行为与影响 | 修复 |
| --- | --- | --- |
| 当前轮次尚未结束，Dock 或续发入口再次发送 | `sendMessageToSession` 直接替换 AbortController 和轮次令牌，清空当前缓冲，再启动执行；旧进程可能仍在运行 | 发送前同时检查同步轮次 store、会话状态和停止屏障；拒绝时保留当前执行、消息及缓冲 |
| 使用后端会话 ID 续发，或某标签 ID 与另一标签的后端别名相同 | 续发仅按标签 ID 查找；执行解析的合并条件可能先命中另一标签 | 续发复用执行解析，并优先精确标签 ID，再匹配后端别名；实际派发统一使用稳定标签 ID |
| 终端 worker 成功完成但没有正文 | 完成分支安排磁盘恢复后直接返回，未消费 nonce、提交终态或通知完成；没有后续输出时可持续占用车道 | 正常提交完成状态与通知，保留原有三次延迟磁盘恢复 |
| 新轮次尚未产生助手消息 | 完成预览会回溯到上一轮回复；失败时旧正文还能掩盖本轮无回复提示 | 正文提取在当前用户消息处停止；完成时的无回复判定使用同一规则 |
| 非 Claude 引擎多次执行，或 Claude 长驻会话多次续发 | 旧 invocation / session 监听仍登记；回调动态读取新 nonce，迟到事件可能影响新轮次 | 各引擎在新轮次注册前注销旧监听；注销后已经排队的回调也不再消费 |
| 定向事件监听只注册成功一部分 | 静默退回全局通道后继续启动，输出可能串入另一会话；多窗格路径也可能丢失输出 | 部分注册失败时释放监听并使回调失效；明确报错，允许用户重试，注册成功后才启动 |
| 默认引擎为 Gemini，或从续发/内部调用进入 Gemini 路径 | 派发门闸与实际引擎解析不一致，部分路径可能落入 Claude 分支 | 门闸使用实际引擎解析器；续发和内部引擎入口都明确拒绝尚未支持的 Gemini 主会话执行 |
| 问题回答通过 resume 续接，但启动失败 | 问题先被标记为已回答并清除，导致失败后无法正常重试 | 先同步宿主执行状态，使用稳定标签 ID 发送；启动成功后再标记回答并清除问题 |

主要实现位于 `src/hooks/useClaudeSessions.sessionActions.ts`、`useClaudeSessions.engines.ts`、`useClaudeSessions.helpers.ts`、`useClaudeSessions.ts`，以及 `src/services/claudeStreamRuntime.ts`、`claudeSessionState.ts`、`src/utils/sessionExecuteResolve.ts`。

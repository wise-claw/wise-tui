# 全链路分析与反馈神经网：检查与补强

## 功能定位

全链路分析将当前会话的输入、推理、工具调用、回复、可观测的 HTTP 请求组织成链路列表、序列图和洞察，并支持 JSON / Markdown 导出与 AI 解读。内存转录与对应执行引擎的磁盘日志是会话事实源；代理 trace 是补充证据。没有观测到的 HTTP 应保持推断标识。

反馈神经网在这些洞察上建立“基线 → 独立 worker 优化 → 新轮次比对 → 提炼习惯与配置补丁”的闭环。已有的补丁审阅、低风险自动应用、回滚、回归检测、熔断和审计能力保留。

## 发现的问题与修复

| 问题 | 影响 | 本次处理 |
| --- | --- | --- |
| 单屏布局顶栏没有传会话，内部顶栏被隐藏 | 有对话却提示打开会话 | 实际布局入口传递选中会话，并优先查最新会话 store；工作区主会话作为回退 |
| 分析 / 反馈只读取 Claude JSONL | Codex RPC / Cursor 读错目录与 ID | 共用引擎感知的日志加载；RPC / Cursor 使用 Wise tab ID |
| 日志请求随流式消息条数变化重复触发 | 大会话频繁读盘与清空合并数据 | 根据会话、运行状态与加载窗口刷新，保留同一会话先前数据 |
| 切换会话时日志或筛选状态残留 | 旧数据混入或新内容被旧筛选隐藏 | 隔离加载状态，取消过期请求，重置轮次和筛选 |
| 链路缓存仅比较计数、末条 ID / 时间 | 不同会话或流式更新可能复用旧结果 | 使用不可变来源快照身份隔离缓存；保留缓存上限 |
| 反馈没有订阅会话实时内容 | 新轮次洞察和比对滞后 | 订阅锚定会话的 live store |
| 更多菜单关闭就卸载反馈控制器 | worker 完成后无人接收、自动闭环停止推进 | 隐藏入口保持挂载，用 controlled open 控制抽屉 |
| idle worker 注册时被误判成功，completed / cancelled 未被识别 | 空任务假成功，单次任务永久等待 | 空闲必须有本次派发的助手响应；识别完成、取消和错误；空完成视为失败 |
| execute 抛错没有更新派发记录；失败没有终止闭环 | 历史一直运行、闭环等待没有启动的任务 | 记录失败、向闭环传递错误并停止，显示原因 |
| 无数据或无执行能力仍能启动闭环 | 无效优化与等待 | UI 和状态入口都检查轮次与派发能力 |
| 多屏 AI 解读沿用全局回调 | 在错误会话执行分析 | 每个窗格绑定自己的执行回调 |
| createdAt 会因排序更新而缩短 trace 时间范围 | 早期请求遗漏 | 从已知消息时间与 createdAt 取最早值 |

加载错误在两个界面中均有说明和重试，内存数据仍可用。

## 验证范围与边界

测试覆盖引擎日志定位、过期请求、重试、无会话状态、缓存隔离、流式更新、worker 状态和一次性结果回收；同时运行现有洞察、闭环状态机与工具动作测试及 TypeScript 检查。

HTTP 代理仍有部分基于时间的归属推断：没有会话 ID 的 trace 在多会话并发时不能证明精确归属。完整改进需要采集层的请求关联 ID，当前不得把时间匹配当作确切归属。

关闭反馈抽屉可继续当前锚定会话的闭环；切换锚定会话后，旧锚点的控制器仍依赖重新打开恢复。要支持跨会话持续自动优化，应将闭环执行器统一迁移到 Automation 运行层，并保留现有会话状态和补丁审计数据。

安装版使用打包资源，不会加载开发目录的源码修改。发布前还需在实际目标版本验收：选中有内容的 Codex 会话 → 全链路分析出现链路 / 洞察；打开反馈 → 派发独立 worker → 关闭抽屉 → 任务完成 → 重新打开可看到结果。
